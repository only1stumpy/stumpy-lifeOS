# Промо-ролики LifeOS

Ролики делаются в проекте `~/Projects/lifeos-promo` (Remotion, React, TypeScript), рядом с репозиторием `~/Projects/Stumpy_LifeOS`. Репозиторий приложения — только источник правды: читать можно, менять и коммитить нельзя, если пользователь отдельно не попросил.

## Посыл (обязательно)

- Это **промо перед релизом LifeOS 1.0**: подогреть аудиторию. Плашка или строка «Скоро релиз LifeOS 1.0».
- **Бот пока закрыт.** Тег бота (`@stumpy_lifeos_bot`) нигде не показывать: ни в кадре, ни в описании.
- Призыв в конце: бета-тест через личку. Контакт: **Telegram: @only1stumpy**. Не «Леон Стампель», не тег бота.
- Не писать «бот уже открыт», «пробуй сейчас», «идёт закрытый бета-тест с доступом через бота».
- Без выдуманных метрик, рейтингов, отзывов, «секунд на запись». Скорость показывать хореографией.

## Демо-данные

- Валюта — просто **рубли**: в чате `85,00 руб.` (формат `formatMoneyPlain`, разряды через пробел: `1 230,00 руб.`), в Mini App `руб.`, имя счёта «Зарплатная карта · Рубль». **Никакого «ПМР» и «PRB» в кадре.**
- Цены в масштабе ×5 к «бытовым»: удон 425, такси 600, кофе 900, зарплата 75 000, баланс ~40–90 тыс., чек ~1 230. Держать масштаб единым в одном ролике.
- Все числа демонстрационные: внутри ролика они должны сходиться (баланс до/после = ± сумма операции).

## Тексты бота — только дословно из кода

Перед новой сценой найти реальный текст в `~/Projects/Stumpy_LifeOS/src/server/telegram/`. Каталог проверенных текстов — `references/bot-texts.md`. Если поведение в коде не совпадает со сценарием, менять сценарий, а не текст бота. Если в реальном выводе бота есть неаккуратность (например, «72.4 кг», но «-0,4 кг»), выбрать демо-значения, на которых она не видна, и сказать об этом пользователю.

## Визуальные правила (DESIGN.md + поправки пользователя)

- Светлый Liquid Glass, фон `#f6f2ec → #f1e9eb → #f7f1ec` с дрейфующими мягкими полями, текст `#35272c`/`#76666d`, акцент `#742b45`, стекло ~8.5% белого, `blur(9px) saturate(1.3)`, радиусы 28/27/999. Шрифты Medeo Sans/Mono из `public/fonts`. Токены — только `src/tokens.ts`.
- Без эмодзи в кадре, без логотипов Telegram и чужих брендов, без рамки телефона, без капса. Подписи ≥ 40 px, заголовки 80–120 px.
- Безопасные зоны 1080×1920: сверху ≥ 220 px, снизу ≥ 340 px без важного текста.
- Чат стилизован под LifeOS: исходящий пузырь бордовый, входящий стеклянный, «Записать» сплошным бордовым.
- **Кнопки под сообщением — ровно по ширине своего пузыря**, не шире (`Draft` в `src/chat.tsx`).
- **Строки списков** (операции, дневник) — высота с запасом под двустрочную подпись. Текст не должен наезжать на разделитель.
- **Обводка тапа** — с отступом от элемента (inset от −12, расходится наружу), не впритык к контенту.
- **Шестерёнка в доке** — симметричная 8-зубцовая (`settings` в `src/app.tsx`), не путь из приложения.
- Смена экранов в окне приложения — с перекрытием (новый входит сразу, старый уходит), каскад начинается чуть раньше смены. Пустых кадров быть не должно.
- Новые компоненты Mini App оборачивать в `fontFamily: FONT_SANS`, иначе подхватывается серифный системный шрифт.
- Камера: каждый ключ проверять стиллом, контент не должен уходить под док или за край окна.

## Структура проекта

- `src/config.ts` — тексты, подписи, финал, тайминги, звук, демо-данные. Секции по роликам: `config` (Promo), `day`, `fix`, `money`, `quit`, `duel`, `apps`.
- `src/tokens.ts`, `src/anim.ts` (пружины `sp`, `tw`, `appear`, `press`, `typedCount`/`typingDuration`, `camera`).
- `src/ui.tsx` — `Background`, `Glass`, `Caption` (`at`/`until`/`top`/`size`), `TapRing`.
- `src/chat.tsx` — `OutBubble`, `InBubble`, `Draft` (подмена на подтверждение, `tapAt`/`confirmAt`/`rows`/`tapLabel`), `Keyboard`, `StatusBubble`, `Receipt`.
- `src/app.tsx` — экраны Mini App (`NutritionScreen`, `Finance*`, `Gym*`, `Today`…), `AppWindow` (окно с камерой и доком, `dock=[{t,tab}]`), `Dock`.
- `src/parts.tsx` — общие куски коротких роликов: `Hook`, `FinalCard`, `linkLayout` (чат уезжает вниз, сверху окно), `windowIn`.
- Ролики (композиции в `src/Root.tsx`, старые не ломать): `Promo.tsx` + `scenes.tsx` (52 с), `Day.tsx` (30 с), `Fix.tsx` (18,6 с), `Money.tsx` (21,2 с), `Quit.tsx` (18,1 с), `Duel.tsx` (19,3 с), `Apps.tsx` (25,8 с).
- `scripts/make-audio.mjs` — синтез звука (клики набора, тики тапов, «записал», тихие клики ячеек). Тайминги там дублируют `*Times()` из роликов: **после любого сдвига таймингов или текста набора обновить блок ролика в скрипте и запустить `npm run audio`**.
- `scripts/stills.sh` — контрольные кадры: `COMP=Day scripts/stills.sh 120 300` (половинный масштаб).

## Уроки из роликов 3–7

- Нейтральные «чужие» приложения (трекер, таблица, три карточки) рисовать безымянными и серо-белыми, без брендов; называть обобщённо («Калории», «Бюджет», «Тренировки»).
- Цифры сравнения («40 против 4») постановочные: ускоренную сторону подписывать («ускорено ×5»), реальных замеров не заявлять. В «Apps» секунд нет совсем, сравнение считаем входами и формами.
- Зал в продукте вводится в Mini App, не текстом: в сравнениях показывать окно Mini App внутри Телеграма, не «записал подход в чате».
- Подтверждение «Записать все» в боте — отдельный ответ `Записано N из M` + строки; в кадре безопасна только первая строка.
- `Draft` обрезает высоту по числу строк: длинные строки бота разбивать вручную на строки, как они переносятся, иначе текст режется.
- Окно с `dock` ниже 780 px не вмещает три строки подходов: брать `h≥940`, камеру `y≈245`, чат ужимать до `scale 0.5`.
- Контентный блок в панели `scale ≈ 0.58–0.62` читается, меньше — нет.
- Описание для ТикТока к каждому ролику выдаётся сразу вместе с файлом (см. «Рабочий цикл», п. 5).

## Рабочий цикл

1. Сценарий → сверка текстов бота с кодом → правки `config.ts`/сцен.
2. После каждой сцены — стиллы ключевых кадров и **посмотреть картинки** (склейка `ffmpeg … hstack`).
3. `npx tsc --noEmit`, затем рендер:
   ```bash
   npx remotion render src/index.ts <Promo|Day|…> out/<имя>.mp4 --codec=h264 --crf=18 --pixel-format=yuv420p --concurrency=6
   ffmpeg -i out/<имя>.mp4 -c copy -movflags +faststart out/fs.mp4 && mv out/fs.mp4 out/<имя>.mp4
   ```
   Рендер идёт через системный `/usr/bin/google-chrome` (`remotion.config.ts`): собственный браузер Remotion не скачивается в этой сети (IPv6).
4. `ffprobe`: 1080×1920, 30 fps, yuv420p, нужная длительность, есть аудиопоток. Contact sheet (`fps=1` или `2`, `tile`) — пройтись глазами.
5. Отправить файл через SendUserFile и **в том же ответе дать описание для ТикТока**: 2–4 строки о сервисе и сути ролика, «Скоро релиз LifeOS 1.0», «Хочешь в бета-тест? Пиши в Telegram: @only1stumpy», ровно 5 хэштегов (базовый набор: `#lifeos #продуктивность #подсчеткалорий #учетфинансов #телеграмбот`). Текст описания чистый, без мата.

## Звук

- Громкий: нормализация пика до −0.5 dBFS в скрипте, `audio.volume: 1`. Пользователь кладёт поверх свою музыку, стоковой музыки не добавлять.
- Если пользователь говорит «звука нет» — сначала проверить файл (`ffprobe`, `astats` по секундам), отправить `public/audio/*.wav` отдельно и напомнить про mute в галерее телефона.

## Как принимать правки

- Если пользователь говорит «сохрани правку, ничего не меняй» — только подтвердить и пронумеровать её одной-двумя строками, не трогать файлы, пока не скажет «приступай».
- Затем внести все правки разом, проверить стиллами именно те места, перерендерить, отправить.
- Ошибочный посыл (открыт/закрыт бот, контакт, валюта) исправлять сразу и по всем местам: кадр, `config.ts`, notes, описание.

## Мелочи окружения

- Bash в этой системе печатает баннер neofetch перед каждым выводом: держать вывод команд коротким или писать в файл и читать через Read; не резать вывод `tail -n +N`, это съедает полезные строки.
