# Техническая основа LifeOS

Состояние на 28 октября 2026 года. Production-развёртывание в Vercel, база Neon и Telegram webhook подключены. Gemini задан в Vercel Production, cron-job.org настроен для ежедневного вызова; тест `/api/cron` вернул `200 OK`. Все три миграции применены. Новый Liquid Glass стиль, календарь полной истории КБЖУ и обзор финансов с приоритетным балансом основного счёта развернуты; суммы операций показываются со знаком по типу операции. Главный экран также показывает расчётный баланс и расходы за сегодня. Визуальную работу интерфейса, fullscreen и safe-area ещё нужно проверить в целевом Telegram WebView; фактическая доставка сводок и качество разбора ИИ тоже не подтверждены.

| Расписание | Защищённый маршрут сводок | cron-job.org настроен; тест `/api/cron` вернул `200 OK`, доставка уведомлений не проверена |
| Дизайн | Medeo, Liquid Glass с SVG-преломлением и CSS-fallback | Код есть; поддержка реальными Telegram WebView не проверена |

Точные версии зависимостей задаёт `package.json`; TypeScript закреплён на `5.9.3`, `package-lock.json` фиксирует разрешённое дерево. В `next.config.ts` выставлен `experimental.useTypeScriptCli: false`, чтобы Next.js использовал TypeScript API. Требуется Node.js `>=22`. Установка выполняется через `npm ci`.

В приложении нет отдельного сервера, Redis, банковской синхронизации или чужого движка. Исходные изображения еды передаются облачному ИИ во время разбора, но приложение не сохраняет их в собственной постоянной базе. Провайдер обрабатывает полученные данные по своим условиям; LifeOS не контролирует его хранение.

## Приложение и API

Интерфейс, серверные маршруты и доменная логика находятся в одном Next.js-проекте. На совместимых Telegram-клиентах Mini App после инициализации вызывает `requestFullscreen()`; при отсутствии поддержки остаётся обычное развёрнутое представление. Клиент читает `isFullscreen`, `safeAreaInset` и `contentSafeAreaInset` из Telegram WebApp API и обновляет их по событиям изменения fullscreen и safe area. В fullscreen шапка резервирует минимум 80 px сверху, а также учитывает безопасные отступы; обычное развёрнутое представление сохраняет компактную шапку. Пользователь обнаружил наложение меню Telegram на шапку в Android; исправление развернуто, визуальная проверка в Telegram WebView ещё нужна.

Основные вызовы Mini App требуют заголовок `Authorization: tma <Telegram initData>`; сервер сверяет подпись и срок данных и использует проверенный Telegram ID для выбора отдельного профиля. Клиентский `initDataUnsafe` сам по себе не используется для авторизации. Для API-проверки срок `initData` по умолчанию — 24 часа. `TELEGRAM_OWNER_ID` необязателен и задаёт только legacy-аккаунт для общих deployment ключей и квот Gemini.

| Метод и путь | Назначение | Доступ |
|---|---|---|
| `GET /api/snapshot?date=YYYY-MM-DD` | Данные выбранного дня, история и сводные отчёты | Telegram `initData` пользователя |
| `POST /api/commands` | Проверенная Zod команда, затем обновлённый снимок данных | Telegram `initData` пользователя |
| `GET /api/ai-providers` | Список собственных профилей провайдеров без ключей | Telegram `initData` пользователя; `Cache-Control: no-store` |
| `POST /api/ai-providers` | Создание или обновление BYOK-профиля | Telegram `initData` пользователя |
| `DELETE /api/ai-providers?id=...` | Удаление собственного BYOK-профиля | Telegram `initData` пользователя |
| `GET /api/ai-quotas` | Квоты Gemini из Cloud Monitoring для текущей модели | Telegram `initData` legacy-владельца; `Cache-Control: no-store` |
| `POST /api/telegram` | Приём Telegram update, сохранение события и обработка бота | Секретный заголовок Telegram webhook |
| `GET` или `POST /api/cron` | Повтор обработок, напоминания и ежедневная/недельная сводка | `Authorization: Bearer <CRON_SECRET>` |
| `GET /api/export` | JSON-копия данных текущего пользователя | Telegram `initData` пользователя |

Маршруты заданы в `src/app/api/`. Команды и их поля — в `src/domain/commands.ts`. Бот отвечает на `/start`, `/today` и `/cancel`, а также обрабатывает сообщения, фотографии и кнопки подтверждения.

## Данные и миграции

Текущая схема `src/db/schema.ts` описывает 22 таблицы для настроек пользователя, Telegram-событий, черновиков, целей и питания, массы тела, счетов/категорий/курсов/операций/регулярных платежей, упражнений, программы, тренировок, подходов и зашифрованных BYOK-профилей. Все предметные запросы ограничены ID профиля. Миграции находятся в `drizzle/`: `0000_lifeos_initial.sql` создаёт схему, `0001_neat_dormammu.sql` добавляет якорные день и месяц для дат повторяющихся платежей, `0002_watery_toad_men.sql` добавляет историю уточнения, `0003_nebulous_omega_red.sql` добавляет таблицу пользовательских AI-провайдеров. Четвёртая миграция ещё должна быть применена к production; журнал и snapshots Drizzle лежат в `drizzle/meta/`.

Все пользовательские данные связаны с отдельным Telegram-профилем через `ownerId`, ссылающийся на `ownerSettings`. Telegram ID проверяется подписью Bot API перед каждой Mini App операцией и при обработке личного чата. Суммы хранятся в исходной валюте. Внутренний код `PRB` означает приднестровский рубль, а не российский `RUB`; на старте поддерживаются только `PRB` и `USD`.

История КБЖУ для календаря строится из всех сохранённых записей питания и группируется по локальной дате владельца. Новая таблица и миграция не нужны: `nutritionDays` содержит каждую дату с едой и текущую дату, даже если в ней пока нет записей. Отчёт расходов `expenseDays` сохраняет отдельное ограничение последними 31 днями. Календарь не трактует отсутствие записей как нулевое потребление.

USD-операция хранит снимок ручного курса, действовавшего для времени этой операции. При вводе курса задаётся дата начала его действия; новый курс не переоценивает уже сохранённые операции. Валютного сервиса и синхронизации остатков нет.

Финансовая операция хранит положительную сумму в minor units; знак отображения определяется типом операции: расход — минус, доход — плюс. Эта визуальная подпись не меняет формулу остатка счёта. Обзор вкладки «Финансы» сначала показывает расчётный баланс основного счёта, а расходы за день и месяц располагает ниже.

`npm run db:generate` создаёт миграцию по Drizzle-схеме; `npm run db:migrate` применяет её к `DATABASE_URL`. Все три миграции применены к production Neon. Локальный запуск команды против production отдельно не проверялся.

## Сообщения, ИИ и подтверждения

Telegram webhook проверяет секрет, сохраняет update в БД и возвращает ответ Telegram; обработку продолжает Next.js `after()` внутри времени жизни функции. Production webhook зарегистрирован и шесть Telegram updates получили статус `processed` в Neon. Ошибки и зависшие события могут быть повторены cron-маршрутом до трёх попыток. `after()` ограничен серверной функцией и не является долговечной очередью; повторы и обработка в Telegram WebView отдельно не проверялись.

Разбор использует пользовательские OpenAI-compatible профили в настроенном порядке; профиль хранит HTTPS endpoint, имя модели и зашифрованный API-ключ. Пользовательские запросы отправляются провайдеру напрямую по HTTPS, а стоимость и квоты определяет пользователь. Endpoint валидируется на сервере: запрещаются HTTP, приватные/зарезервированные адреса, DNS-ответы с непубличным IP и редиректы; DNS-адреса фиксируются на время исходящего TLS-запроса. Это ограничивает SSRF для публичного приложения, поэтому локальные/private endpoints не поддерживаются. Legacy Gemini/Groq ключи окружения добавляются в fallback только для Telegram ID из `TELEGRAM_OWNER_ID`.

Если все настроенные провайдеры отказали, Telegram и Mini App показывают безопасное объяснение причины: Gemini `402` или явный `payment_required` означает исчерпанные оплаченные кредиты; `429` — достигнутый лимит квоты/частоты, который не обязательно связан с оплатой; сетевой сбой, таймаут, `408`, `425` или `5xx` — временную недоступность API; ошибки аутентификации, доступа или модели — проблему конфигурации. При разных причинах отказа резерва сообщение перечисляет каждую по провайдеру. Текст ответа провайдера, ключи и содержимое запроса пользователю не раскрываются; неудачный разбор ничего не записывает, остаётся ручной ввод. Основание классификации: [ошибки Gemini API](https://ai.google.dev/gemini-api/docs/api-errors), [ограничения Gemini](https://ai.google.dev/gemini-api/docs/rate-limits), [ошибки Groq API](https://console.groq.com/docs/errors).

Ответ ИИ проверяется схемой Zod; дневные суммы и конвертация вычисляются кодом. Финансовой операции назначается категория по смыслу сообщения; если описание не даёт основания для более точной категории, используется «Прочее». Неотвеченное уточнение хранится как ограниченная текстовая история владельца с TTL 30 минут, передаётся в следующий разбор и очищается при появлении черновика или `/cancel`; истёкшая история очищается при следующем разборе. Еда и обычная финансовая операция сохраняются из черновика только после нажатия «Записать» в Telegram. Редактирование категории остаётся доступным для исправления ошибочного предложения; категория не должна запрашиваться в обычном сценарии. Mini App не показывает повторную панель подтверждения. Если сообщение содержит одну позицию еды и связанный расход, еда и расход остаются в одном черновике и сохраняются одной транзакцией по одному подтверждению. Если в сообщении несколько блюд/напитков и один общий расход, инструкция разбора должна сформировать отдельный черновик с собственным КБЖУ для каждой позиции и отдельный финансовый черновик с `food=null` для общего расхода; всем позициям назначается один `occurredAt`. Каждый черновик имеет независимое подтверждение, общий расход не связан с конкретным блюдом и не дублируется. Это использует существующие `captureDrafts`, `nutritionDrafts` и `moneyDrafts`, не требует новой таблицы, миграции или изменения схемы. После успеха бот называет сохранённые записи и значимые данные, а для черновика с едой и расходом — оба пункта. Повторное подтверждение уже сохранённого черновика не создаёт повторную запись.

API-ключи хранятся как AES-256-GCM ciphertext в `ai_provider_profiles`; браузеру возвращается только `hasApiKey`. Для шифрования обязателен серверный `AI_PROVIDER_ENCRYPTION_KEY` — base64-кодированные 32 случайных байта. Он не хранится в базе; потеря или несовместимая ротация делает ключи расшифровки недоступными. Из-за чувствительности BYOK-профили не входят в экспорт. Скрытая панель метрик Gemini доступна только legacy-владельцу и использует серверные `GOOGLE_CLOUD_SERVICE_ACCOUNT_JSON` и `GOOGLE_CLOUD_PROJECT_ID`.

Справочные вопросы проходят отдельным read-only путём до разбора черновика. Ответы о балансе, тратах, КБЖУ и тренировке формируются из снимка данных; точные суммы и агрегаты выбирает код. Остальные вопросы получают ограниченный JSON-контекст снимка и обрабатываются теми же BYOK-профилями (либо legacy Gemini/Groq для настроенного владельца), без доступа к БД, команд записи или истории диалога. Вопрос не создаёт черновик и не изменяет сохранённую историю уточнения; обычные сообщения о еде и операциях остаются в сценарии записи.

Фото Telegram загружается на время обработки, с ограничением 8 МБ. Успешно обработанный Telegram update очищает сохранённое тело события; в журнале попыток остаются служебные поля. Реальное удаление данных на стороне Telegram или ИИ-провайдера проект не контролирует.

## Часовой пояс и сводки

Часовой пояс каждого профиля по умолчанию — `Europe/Chisinau`; приложение группирует записи и отчёты по локальному дню. Дневная сводка по умолчанию уходит в 19:30, недельная — по воскресеньям в 19:30 по часовому поясу пользователя. Эти значения соответствуют выбранному пользователем ориентиру на вечер и могут переопределяться `DAILY_SUMMARY_TIME` и `WEEKLY_SUMMARY_TIME` в формате `HH:MM`. Значения по умолчанию `19:30` указаны в `.env.example`.

Cron-маршрут также проверяет сроки регулярных платежей и ждёт ручного подтверждения фактической оплаты. cron-job.org настроен на ежедневный вызов в 19:30 по `Europe/Chisinau` с `CRON_SECRET`; ручной тест вернул `200 OK`, автоматическая доставка сводок и напоминаний не проверена.

## Настройка и команды

Скопируйте `.env.example` в `.env`. Основные переменные:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | PostgreSQL для приложения, миграций и резервных копий |
| `TELEGRAM_BOT_TOKEN` | Авторизация Telegram Bot API и проверка Mini App `initData` |
| `TELEGRAM_OWNER_ID` | Необязательный legacy Telegram ID, которому доступны deployment-wide ключи и квоты Gemini |
| `TELEGRAM_WEBHOOK_SECRET` | Проверка входящих Telegram updates |
| `CRON_SECRET` | Защита `/api/cron` |
| `GEMINI_API_KEY` | Подключение Gemini; опционально для ручного ввода |
| `GEMINI_MODEL` | Модель Gemini, по умолчанию `gemini-3.5-flash-lite` |
| `GOOGLE_CLOUD_SERVICE_ACCOUNT_JSON` | Необязательный JSON сервисного аккаунта только для чтения квот Gemini; хранить как секрет сервера |
| `GOOGLE_CLOUD_PROJECT_ID` | Необязательный проект Google Cloud для метрик; по умолчанию берётся из JSON сервисного аккаунта |
| `GROQ_API_KEY`, `GROQ_MODEL` | Необязательный резервный провайдер, модель по умолчанию `qwen/qwen3.8-27b` |
| `AI_PROVIDER_ENCRYPTION_KEY` | Обязателен для сохранения BYOK-профилей: base64 от 32 случайных байт; не терять и не менять без процедуры перешифрования |
| `APP_URL` | HTTPS URL для `npm run telegram:register` |

Команды проекта объявлены в `package.json`:

| Команда | Назначение |
|---|---|
| `npm run dev`, `npm run build`, `npm run start` | Разработка, сборка и production-сервер Next.js |
| `npm run lint`, `npm run typecheck`, `npm test` | Статические проверки и тесты |
| `npm run db:generate`, `npm run db:migrate` | Генерация и применение миграции |
| `npm run telegram:register` | Установка webhook через Telegram Bot API |
| `npm run backup:export -- <file>`, `npm run backup:restore -- <file>` | Экспорт/восстановление JSON-копии |

Резервная копия включает данные приложения и не включает технические строки Telegram updates и доставки уведомлений. Восстановление разрешено лишь для пустого профиля владельца и совпадающего `TELEGRAM_OWNER_ID`; endpoint восстановления через веб не предусмотрен. Реальный экспорт/restore на Neon нужно проверить до личного запуска.

## Что ещё не подтверждено

- Успешный реальный разбор через BYOK-профиль и изоляция на втором Telegram-профиле; доступность бесплатного тарифа определяется провайдером пользователя. Legacy Groq не настроен.
- Автоматическая доставка сводок и напоминаний по расписанию.
- Сквозная работа Mini App через Telegram `initData` с production-базой.
- Реальный разбор привычных блюд и фото этикеток выбранной моделью в пределах бесплатных квот.
- Webhook, Mini App и сводки в реальных Telegram iOS/Android WebView.
- Производственная сборка и визуальная проверка приложения в браузере на поддерживаемых размерах и fallback.
- Настоящий экспорт и восстановление данных владельца.
