# План исправлений по UX-аудиту (0.16.0 – 0.19.0)

Источник: [README.md](README.md) и таблицы по разделам. ID в скобках — номера находок.

## Принципы

- Один PR на релиз, ветки идут стопкой (0.16.0 поверх 0.15.1 и так далее), мерж по порядку.
- Миграций БД в плане нет: удаление дня использует существующий `workout_days.is_archived`, удаление упражнения из дня удаляет только строку плана (история тренировок ссылается на `exercises`, не на строку плана). Если по ходу понадобится миграция, она описывается в PR и применяется только с отдельного разрешения.
- Бизнес-правила не меняются; уточнение одно: операция, датированная раньше первого курса валюты, берёт ближайший заданный курс (раньше отклонялась).
- Каждый релиз: тесты на новую логику, проверка на локальном стенде (390 px, задержка 300 мс), обновление CHANGELOG человеческим языком (без названий миграций, колонок и кода), версия в `package.json` и `package-lock.json`.
- Что стенд не проверяет (Telegram, клавиатура, безопасные зоны), в PR прямо помечается как непроверенное.

## Процесс по каждому PR

1. Ветка, код, тесты, `tsc`, `eslint`, `next build`.
2. Локальный стенд: сценарии из аудита на затронутых экранах.
3. Коммит, пуш, ссылка на создание PR с заполненным названием и описанием.
4. Сообщение от бота LifeOS в Telegram со ссылкой.
