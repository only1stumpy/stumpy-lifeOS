# План реализации

**Статус на 27 октября 2026 года: реализация в репозитории завершена, интеграция и личный запуск не подтверждены.** Код покрывает все три модуля и основные согласованные сценарии. До использования на реальных данных нужно подключить личные сервисы, проверить сквозные сценарии и пройти недельный тест. Этот план описывает оставшуюся проверку, а не недостающие локальные функции.

## Принятый технический контур

- Next.js App Router + TypeScript; Mini App и серверные обработчики в одном проекте.
- Размещение запланировано в Vercel Hobby; код базы использует Neon Serverless PostgreSQL, Drizzle и SQL-миграции.
- grammY webhook; сервер проверяет Telegram `initData`, секрет webhook и ID единственного владельца.
- Zod проверяет команды и структуру ответа ИИ. ИИ предлагается через Gemini, Groq — резерв при настройке ключа и модели.
- Сводки по умолчанию уходят ежедневно в 19:30 и по воскресеньям в 19:30 по часовому поясу владельца. Код допускает переопределение расписания.
- Изображения не хранятся в постоянной базе LifeOS. Перед выпуском проверить все реальные сервисы и их бесплатные квоты.

Точные зависимости — в `package.json` и `package-lock.json`; Node.js `>=22`. Переменные окружения и API перечислены в [архитектуре](architecture.md). Секреты задаются локально и в аккаунтах пользователя, не в документации.

## Оставшаяся проверка и запуск

### 1. Проверить питание на реальных данных

- Проверить реальные текстовые и фото-сценарии, включая этикетки, местные продукты, разбор нескольких приёмов и уточнение предыдущего черновика.
- Убедиться, что приблизительная оценка остаётся помеченной в сохранённом дневнике.
- Убедиться, что отсутствие или ошибка ИИ не теряет пользовательский ввод и что ручная запись остаётся рабочей.
- Проверить расчёт редактируемой цели на параметрах владельца; не выдавать оценку за медицинскую рекомендацию.

### 2. Проверить финансовые сценарии

- Не менять согласованное поведение: каждая обычная чат-операция сначала предлагается как черновик; запись происходит только после «Записать».
- Сохранить исходную валюту и снимок ручного курса, действовавшего на время операции; новое значение не должно менять сохранённую историю.
- Проверить неизвестную категорию, учёт дохода, регулярный платёж, ручной USD→PRB курс и отчёты.

### 3. Проверить журнал тренировок

- Проверить таймер отдыха и продолжение текущей тренировки.
- Проверить поиск, замену и сортировку встроенных и пользовательских упражнений. Каталог и иллюстрации созданы внутри проекта, сторонние каталоги и медиа не копировались.
- Проверить подсказку о возможном повышении нагрузки на результатах выполненных подходов. План автоматически не меняется.
- Проверить вес/повторения, кардио время/дистанцию, перезагрузку во время тренировки и просмотр прогресса.

### 4. Подключить и проверить сервисы

- Настроить Neon, применить обе миграции и проверить снимки/команды на реальной базе.
- Настроить Telegram bot token, owner ID, webhook secret, публичный HTTPS URL и зарегистрировать webhook.
- Проверить бесплатные API-ключи Gemini/Groq и определить приемлемое качество на привычных блюдах. Платное автоматическое переключение не разрешено.
- Развернуть на Vercel и настроить защищённый вызов `/api/cron` через cron-job.org.
- Проверить Telegram iOS/Android WebView, доставку сводок, повтор updates, резервное копирование и восстановление.

### 5. Провести личную неделю

После настройки всех трёх модулей проверить на данных владельца, что он понимает, куда уходят расходы, видит недобор КБЖУ и замечает изменения тренировочных результатов. По итогам исправить реальные неудобства, затем обновить этот статус.

## Команды из `package.json`

```bash
npm ci
cp .env.example .env
npm run dev
npm run lint
npm run typecheck
npm test
npm run build
npm run db:generate
npm run db:migrate
npm run telegram:register
npm run backup:export -- ./lifeos-backup.json
npm run backup:restore -- ./lifeos-backup.json
```

`db:migrate`, webhook-регистрация и резервные копии требуют соответствующих заполненных переменных окружения; webhook-регистрация выполняет внешний вызов Telegram. Restore принимает копию для совпадающего владельца и пустого профиля. Наличие команды не означает, что миграция, Telegram, Vercel, cron-job.org, Gemini/Groq или восстановление на личных данных уже проверены.

## Готовность к повседневному использованию

Первая версия считается готовой, когда все три модуля сохраняют данные в подключённой базе, согласованные сценарии работают из Telegram, ошибки ИИ не теряют ввод, таймер и журнал пригодны в реальной тренировке, расписание доставляет сводки, а экспорт и восстановление проверены. После этого требуется недельное использование для проверки трёх ожидаемых результатов из [продуктовых требований](product.md). До закрытия этих критериев не обозначать приложение как готовое.
