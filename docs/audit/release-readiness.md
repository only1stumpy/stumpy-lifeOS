Дата: 2026-11-15, ветка `docs/audit-release-prep`, версия `0.22.0`. Код и конфигурация не менялись. Сетевых запросов к production не делалось. Всё ниже проверено по файлам и локальным запускам; сомнительное помечено «(?)».

Турбопак не печатает размеры по маршрутам, поэтому размеры взяты из `.next/static/chunks` (сырой / gzip): суммарно JS 1 139 561 Б / 330 185 Б (~322 КБ gzip); крупнейшие чанки 551 КБ / 153 КБ, 229 КБ / 72 КБ, 181 КБ / 48 КБ, 113 КБ / 39 КБ; CSS 104 КБ / 18,5 КБ. Приложение одностраничное (один маршрут `/`), поэтому полный JS ~322 КБ gzip грузится на первом открытии. Шрифты Medeo (~211 КБ по прежнему аудиту `docs/audit-2026-11-12.md`) грузятся с CDN. ## Минимальный набор тестов до RC

1. Диалект команд: тесты `executeCommand` на PGlite (уже в devDependencies) для ключевых команд: запись еды из черновика, запись расхода с курсом, подтверждение и отмена черновика, долг и погашение, `onboarding.complete`, `modules.save`, изоляция двух владельцев (нельзя прочитать/изменить чужое).
2. Миграции: тест «чистая БД + все `drizzle/*.sql` по порядку» на PGlite, что схема совпадает с `src/db/schema.ts` (drizzle-kit `check` или сравнение).
3. API-маршруты: 401 без/с подделанным `initData`, `/api/telegram` с неверным секретом/повтором `update_id` (идемпотентность), `/api/cron` без `CRON_SECRET`.
4. Бот: `processStoredTelegramUpdate` на фейковом Telegram-клиенте: сохранение update → повтор после падения → один раз записанная запись.
5. Один e2e-дымовой: Playwright на локальной сборке (с отладочной подписью `initData`), сценарий «открыть Сегодня → записать еду → видеть обновлённые числа». Не блокер, если есть ручной чек-лист.

## Что уже в порядке

- Чистые tsc, eslint, 109 тестов, сборка, 0 уязвимостей `npm audit --omit=dev`.
- Webhook: проверка секрета константным сравнением, лимит тела 256 КБ, сохранение update до ответа, дедуп по `telegram_updates.update_id` (unique), `after()`, повтор в cron; уведомления дедуплицируются (`notification_deliveries`, `FOR UPDATE`).
- `initData` проверяется подписью и сроком; данные изолированы по Telegram ID; ключи ИИ шифруются AES-256-GCM.
- Индексы по `ownerId` и датам на всех горячих таблицах (21 индекс + уникальные ограничения, включая защиту от повторной записи черновика).
- Бэкап: JSON-экспорт/восстановление с версией формата, лимитами размера и строк, юнит-тестами.
- CHANGELOG ведётся по SemVer 0.MINOR.PATCH с датами и подтягивается в «Что нового»; `engines.node >=22`, зависимости закреплены точно.
- Секреты не в репозитории: `.env*` в `.gitignore` (`.env.local` не отслеживается), `.env.example` без значений.
- Лицензии зависимостей разрешительные; `npm audit` чист.
