# План до первого релиз-кандидата (1.0.0-rc.1)

Составлен по шести аудитам: [код](audit/code-quality.md), [архитектура и SOLID](audit/architecture-solid.md), [безопасность](audit/security.md), [документация](audit/documentation.md), [готовность к релизу](audit/release-readiness.md) и переписанный README. Отчёты аудиторов — статический анализ без запуска production; ключевые находки перепроверены вручную (см. раздел «Что проверено лично»).

## Итог одной страницей

Состояние кода хорошее для беты: `tsc`, `eslint` и 109 тестов чистые, `npm audit --omit=dev` без уязвимостей, изоляция по `owner_id` выдержана, подпись `initData`, шифрование BYOK и защита от SSRF сделаны правильно. До публичного релиза не хватает не «фич», а **эксплуатационной зрелости**: нет CI, лицензии, политики конфиденциальности, удаления данных, наблюдаемости и тестов слоя команд, а cron падает целиком из-за одного пользователя.

| Область | Оценка (из 10) | Главная причина |
|---|---|---|
| Качество кода | 6 | монолиты: `EditorDialog` ~870 строк, `executeCommand` ~335, `bot.ts` 1163 |
| Архитектура (SOLID) | 4–5 | DIP 3: `getDb()`/`ensureOwner()` глобально, SQL в хендлерах бота |
| Безопасность | средний риск, critical нет | cron, удаление данных, rate limit, CSP |
| Документация | 5 | устаревший статус, нет развёртывания, runbook, `SECURITY.md` |
| Готовность к релизу | CI 3, наблюдаемость 2, право 2 | нет `.github`, `LICENSE`, политики |

## Этапы до RC

Каждый этап — отдельный PR от `main` (по одному, после мёрджа предыдущего). Версии ориентировочные.

### Этап 0. Гигиена репозитория (0.23.0), 1–2 дня

- `.github/workflows/ci.yml`: `npm ci`, `lint`, `typecheck`, `test`, `build` на каждый PR и пуш в `main`; `dependabot.yml` (npm, GitHub Actions, еженедельно).
- `LICENSE` (после решения владельца), `SECURITY.md`, `CONTRIBUTING.md`, шаблоны issue/PR.
- Убрать из корня `.aws`, `.codex`, неотслеженный zip (проверить `.gitignore`); решить судьбу `CLAUDE.md`/`AGENTS.md` (сейчас дубли, `CLAUDE.md` не в git).
- Исправить документы по фактам: миграции `0000`–`0013`, любые валюты, `/help`, число таблиц (29), число тестов; пометить исторические документы плашкой и перенести в `docs/archive/`.
- Документировать контракт формата `CHANGELOG.md`, дополнить `.env.example` (`DAILY_SUMMARY_TIME`, `WEEKLY_SUMMARY_TIME`, обязательные/необязательные).
- Первые git-теги и GitHub Release для текущей беты; защита ветки `main` (настройка GitHub, делает владелец).

### Этап 1. Надёжность и безопасность (0.24.0), 3–5 дней

- Cron: `try/catch` на владельца с логом причины, `ORDER BY`, ограничение времени на прогон; `processStoredTelegramUpdate` и около 15 `.catch(() => undefined)` — логировать причину.
- Убрать fail-open: удалить `TELEGRAM_OWNER_ID` как запасного владельца и ветки env-ключей ИИ в `analyze.ts` (около 350 строк мёртвого legacy-кода); метрики Gemini оставить отдельно и явно.
- `executeCommand`: добавить `default` с проверкой исчерпанности (`never`), чтобы незнакомая команда падала, а не молчала.
- Заголовки безопасности в `next.config.ts`: CSP, `frame-ancestors` (разрешить Telegram), `nosniff`, `Referrer-Policy`, HSTS.
- Проверка при старте: длина и случайность `CRON_SECRET`, `TELEGRAM_WEBHOOK_SECRET`, наличие `AI_PROVIDER_ENCRYPTION_KEY`.
- Исправления целостности финансов (A8): удаление записи-возврата не должно давать 500; `draft.reject` на подтверждённом черновике — явная ошибка.
- Health-эндпоинт без секретов и единый лог ошибок (без персональных данных).

### Этап 2. Данные пользователя и право (0.25.0), 3–5 дней

- Политика конфиденциальности и согласие при первом входе (текст согласовать с владельцем; указать: данные в Neon, ключи ИИ шифруются, ИИ-провайдеры получают только отправленные пользователем тексты и фото).
- Команда и экран «Удалить мои данные» с подтверждением необратимости; каскад по всем таблицам владельца, проверка в PGlite.
- Кнопка экспорта в настройках; срок хранения payload упавших апдейтов (очистка по cron).
- Бэкап: права `0600`, опциональное шифрование; проверенная процедура restore на ветке Neon; runbook в `docs/operations.md`.

### Этап 3. Тесты слоя команд (0.26.0), 3–4 дня

- Тесты `executeCommand` на PGlite (он уже в devDependencies и прогоняет все миграции): сценарии по каждому модулю, изоляция двух владельцев, конкурентные команды.
- Тесты cron-маршрута и webhook (повтор update, неудачная доставка), контракт `/api/*` (401 без подписи, чужие id).
- Минимальный e2e дымового уровня в CI (запуск сборки и обращение к `/` и `/api/health`).

### Этап 4. Производительность и сопровождаемость (0.27.0–0.28.0), 1–2 недели

- `loadSnapshot` (22 запроса по всей истории): окно по датам и пагинация истории; замеры до и после.
- Единые `formatMoney`/`plural`/расчёт остатка долга вместо 5 + 4 + 6 копий (A7); вынести общий кэш `Intl`.
- Постепенно разрезать монолиты под защитой новых тестов: `bot.ts` на хендлеры по модулям, `executeCommand` на реестр обработчиков по доменам, `EditorDialog` на формы по разделам. Без остановки разработки, по одному PR.
- Prettier, CSS-токены вместо 53 повторов `#742b45` и 28 `!important`.

### Этап 5. Сквозная проверка (0.29.0), 1 неделя, часть делает владелец

Нужны реальные устройства и аккаунты, на стенде это не проверить.

- Telegram WebView на iOS и Android: safe area, клавиатура, полный экран, кнопка «Назад».
- BYOK end-to-end по каждому провайдеру (Gemini, Groq, OpenRouter, свой endpoint): подключение, проверка ключа, fallback, исчерпанная квота.
- cron-job.org: напоминания, сводки, повтор зависших update.
- Лицензия шрифтов Medeo (сейчас с CDN, лицензия не зафиксирована): решение о самохостинге или замене.
- Проход по доступности (WCAG AA: контраст уже подтянут в 0.20.0).

### Этап 6. Выпуск RC (1.0.0-rc.1)

- Заморозка функций, регрессионный чек-лист, тег, GitHub Release с заметками из `CHANGELOG.md`.
- Закрытая группа бета-тестеров, канал обратной связи (issues или чат), 1–2 недели наблюдения.
- Критерий выхода RC в 1.0.0: нет открытых blocker/high, CI зелёный, restore проверен, 0 необработанных ошибок cron за неделю.

## Определение готовности RC

- Все блокеры B1–B10 закрыты.
- CI на `main` зелёный, защита ветки включена.
- Политика конфиденциальности, согласие, удаление и экспорт данных работают на проде.
- Cron устойчив к отказу одного пользователя, ошибки видны в логах.
- Слой команд покрыт тестами, `switch` проверяется на исчерпанность.
- Документация соответствует коду, есть руководство по развёртыванию с нуля и runbook.
- Пройдена сквозная проверка этапа 5.

## После релиза (не блокирует RC)

- Остальные находки из [code-quality](audit/code-quality.md) и [architecture-solid](audit/architecture-solid.md) с пометкой low/medium.
