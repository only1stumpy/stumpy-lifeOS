# Вклад в проект

Спасибо за интерес. Проект ведёт один человек, поэтому перед большой работой откройте issue и обсудите идею.

## Лицензия вклада

Код распространяется по [GNU AGPL-3.0](LICENSE). Отправляя PR, вы соглашаетесь, что ваш вклад распространяется на тех же условиях. Авторские права на ваш вклад остаются за вами.

## Как внести изменение

1. Форкните репозиторий и создайте ветку от `main`.
2. Установите зависимости: `npm ci`.
3. Перед PR запустите `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` (то же делает CI).
4. Изменение поведения для пользователя поднимает версию (см. «Версии» ниже) в `package.json` и `package-lock.json` и добавляет раздел в [CHANGELOG.md](CHANGELOG.md). Формат раздела: заголовок `## X.Y.Z · ГГГГ-ММ-ДД` и строки `- ...` (сборка разбирает этот файл для окна «Что нового»).
5. Бейджи и версия в README генерируются из `package.json`; после зелёных проверок CI сам коммитит обновление README в ветку PR (вручную `npm run docs:readme` нужен только локально). Чтобы проверки прошли и на коммите бота, добавьте секрет `README_SYNC_TOKEN`.
6. Миграции БД описывайте в PR и не применяйте к production без разрешения владельца.
7. Не добавляйте секреты, ключи и персональные данные в код, документы и описания.

## Версии

Выпуски идут по SemVer: `1.MINOR.PATCH` после `1.0.0`. `PATCH` — только исправления; `MINOR` — новое или изменённое поведение без ломки данных и API; `MAJOR` — несовместимое изменение (формат экспорта, схема, поведение API). Миграции БД только вперёд и обратно совместимы с предыдущим деплоем, пока PR не слит (миграция применяется до merge). Версия `0.x`/`1.0.0-rc.N` в истории CHANGELOG — предрелизная. Версию поднимает PR, который меняет поведение для пользователя; правки документации и тестов её не меняют.

## Правила кода

- Бизнес-правила живут в `src/domain`, их используют и бот, и Mini App; арифметика денег и КБЖУ выполняется кодом, не ИИ.
- Отступы Telegram только через `--lifeos-inset-top` и `--lifeos-inset-bottom` (проверяет `tests/safe-area.test.ts`).
- Дизайн: светлый Liquid Glass, бордовый акцент, без эмодзи; перед изменением интерфейса прочитайте [DESIGN.md](DESIGN.md).
- Коммиты, PR и документация пишутся нейтрально.

Безопасность: см. [SECURITY.md](SECURITY.md).
